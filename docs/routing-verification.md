# 라우팅 검증 (2026-07-31)

`router.py`를 규칙 기반(정규식/신호단어)에서 LLM 구조화 출력 하나로 전면 교체한 뒤,
12개 질문으로 정리/비교/집계/검색 + 다중 기간 케이스를 검증한 기록.

## 배경

- 원래 문제: "저번주 정리 그리고 이번주와 비교"처럼 기간이 여러 개 섞인 질문에서
  규칙 기반 라우팅(`find_date_range`가 정규식 우선순위로 기간 하나만 뽑음)이 깨짐
- 대응: `route()`를 LLM 구조화 출력 하나로 교체 — `app`/`hour`/`periods`(기간 리스트,
  여러 개 가능)/`intent`를 한 번의 호출로 뽑음
- 이 과정에서 발견하고 고친 버그:
  - intent 분류가 "이번 주 언제가 제일 바빴어?"를 집계로 잘못 판단 → 프롬프트에
    반례 예시 추가해서 수정
  - 기간이 2개 이상인 집계 질문(`카카오톡을 저번주엔 몇 번, 이번주엔 몇 번 켰어?`)이
    `compare_periods()`(LLM이 요약문 보고 비교)로 흘러가서 실제 340회를 "5회"로
    잘못 답함 → intent별로 분기해서 집계는 `count_range()`로 직접 세도록 수정
  - Anthropic 구조화 출력 스키마 호환성 문제(enum+nullable 조합, integer
    min/max 미지원) → `anyOf` 패턴으로 스키마 수정, hour 범위는 후처리 검증으로 이동
  - LLM이 요일을 직접 계산하다 오답(7/27을 일요일로 답함) → `weekday_ko()`로
    날짜 라벨에 요일을 미리 계산해서 프롬프트에 박아 넣음

## 검증 결과

| # | 유형 | 질문 | 라우팅 결과 (app/hour/intent/periods) | 판정 |
|---|---|---|---|---|
| 1 | 정리(단일기간) | 이번 주에 주로 무슨 일을 했어? | intent=정리, 이번 주(5일) | ✅ 요일 포함 하루씩 정상 요약 |
| 2 | 비교(날짜간) | 이번 주 언제가 제일 바빴어? | intent=비교, 이번 주(5일) | ✅ "7/29(수)"로 요일까지 정확 |
| 3 | 집계(단일기간) | 이번 주에 카카오톡을 몇 번 켰어? | app=카카오톡, intent=집계 | ✅ 496회 (metadata 실측과 일치) |
| 4 | 검색(기간없음) | 카카오톡에서 무슨 대화를 했어? | app=카카오톡, periods=[] | ✅ 근거 인용 정상 |
| 5 | 검색(앱+시각) | 오후 3시에 zoom에서 뭐 하고 있었어? | app=zoom.us, hour=15, date=오늘 | ⚠️ "기록 없음" — 라우팅은 맞는데 오늘 15시 zoom 기록 자체가 없어서(데이터 문제, 로직 문제 아님) |
| 6 | 검색(단일날짜) | 어제 뭐 했어? | date=2026-07-30 | ✅ 요일 포함 정상 |
| 7 | 정리(다중기간) | 저번주랑 이번주 각각 정리해줘 | intent=정리, 저번주(7일)+이번주(5일) | ✅ 기간별로 나란히 요약 (비교 호출 없음) |
| 8 | 비교(다중기간) | 저번주 정리 그리고 이번주와 비교 | intent=비교, 저번주+이번주 | ✅ 기간별 요약+비교 정상 (원래 실패했던 케이스) |
| 9 | 집계(다중기간) | 카카오톡을 저번주엔/이번주엔 몇 번 | intent=집계, 저번주+이번주 | ✅ 340회/496회, 실측과 정확히 일치 |
| 10 | 겹침 엣지 | 어떤 앱을 가장 많이 썼는지 비교해줘 | intent=집계 | ✅ "가장 많이 쓴 게 뭐냐"는 본질적으로 카운트 질문이라 집계가 맞는 분류 |
| 11 | 사전에 없는 표현 | 화상회의 앱에서 뭐 했어? | app=zoom.us (LLM이 알아서 매핑) | ✅ "화상회의"→zoom.us 정상 추론 |
| 12 | 최근 N일 | 최근 5일간 정리해줘 | intent=정리, 최근 5일(5일) | ✅ 정상 |

## 결론

12개 중 11개 완전 정상, 1개(#5)는 라우팅은 맞았는데 그 시간대 실제 데이터가
없어서 "기록 없음"이 나온 것(코드 문제 아님). 예전에 겪었던 문제들(기간 여러 개
파싱 실패, 집계인데 LLM이 잘못 세는 것, 요일 오답)은 재현되지 않음.

## 참고: OpenAI vs Anthropic 답변 차이

같은 근거로 "이번 주 언제가 제일 바빴어?"를 물었을 때:

- **OpenAI(gemini-3.1-flash-lite)**: 활동의 다양성(도구 종류) 기준으로 판단, 목록형 서술
- **Anthropic(claude-haiku-4-5)**: 연속 활동 시간 기준으로 판단, 서술형 문장

"바쁘다"의 판단 기준(다양성 vs 지속시간)이 모델마다 달라 결론(어느 날이 제일
바빴는지)이 갈릴 수 있음 — 버그가 아니라 모델 차이. 요일 계산을 프롬프트에서
미리 넣어준 뒤로는 두 모델 다 요일 오류 없음.
